# 棋盘 MOBA 程序对抗赛

目标是在限时内做出尽可能强的队伍程序，在不同对手、种子和红蓝两边都能稳定发挥。

## 开发与收卷时间

- **开赛后 0–180 分钟**用于开发、试赛和调整阵容。
- **开赛后 180–210 分钟**用于整理成绩、填写名单和打包提交。
- **开赛满 210 分钟**裁判强制收卷，以截止前收到并通过校验的正式提交为准。可以提前交卷，正式提交即封存阵容。

请尽可能充分利用开发时间。拿不准还剩多久时，随时查表。先跑通一支能完整完赛的队伍做保底，再把剩余时间用来修正反复出现的问题和复验。拿到裁判发的 `contest-clock.json` 后，运行 `node referee.cjs time_left` 查看开发和交卷还剩多久。

如果平台、裁判服务或参赛任务意外中断，恢复后由裁判按确认的停摆时长补时。开发期中断会顺延开发结束和收卷时间，整理期中断会顺延收卷时间。恢复后先重新查表，按裁判更新的截止时间安排工作。

## 试赛和迭代

可以先看一组基准互打的换边回放，熟悉分路、资源刷新、开团和推进。开发时，用自己的队伍跟基准对打，也让自己的不同方案互打。用同一种子交换红蓝，结合输局回放找出具体问题。改完再用更多种子复验，把能稳定带来提升的改动留下来。裁判提供公开规则、成绩和可申请的回放，两套基准的源码由裁判保管。

## 选手 ID 与核心

在队伍目录的 `roster.json` 中为上单、中单、打野、射手、辅助各填一个 ID，再从这五个位置中指定一名核心。每个 ID 用 1–10 个英文字母或数字，两者可以混用。取名可以借用自己模型的梗、小说或动漫角色、历史人物、电竞梗，也可以原创。下面是打野担任核心的示例。

```json
{
  "coreRole": "jungle",
  "playerIds": {
    "top": "LuBu",
    "mid": "Gojo",
    "jungle": "Baron",
    "adc": "Uzi",
    "support": "Paimon"
  }
}
```

地图阶段，核心先按公开棋盘提交一条提案，其他四个位置各自根据公开棋盘和同一份核心提案作决定。四人可以通过 `decide(observation, reference)` 接收第二个参数，读取 `reference.coreRole` 和 `reference.coreOrder`。核心可以提 `null`。核心的提案只发给本队，四个队友各自只收到这一份提案。

最后，教练通过 `decide(observation, proposals)` 看齐己方提案，可替换其中一条，包括核心自己的提案。教练开团有独立冷却，占用被点名英雄的当回合行动。两边交齐后同时结算地图伤害。最终决战按公布顺序行动，只询问当前行动的选手。单队每回合最多用时 2000ms。

## 提交与迭代

每份阵容包含 `roster.json` 和六个同步 CommonJS 模块 `top.cjs`、`mid.cjs`、`jungle.cjs`、`adc.cjs`、`support.cjs`、`coach.cjs`。开发时可随时改候选队伍的核心再试赛。正式提交后，五个 ID、核心和六份程序一起封存，复验使用同一份阵容。

通过工作台裁判接口上传并提交最终队伍。**正式交卷前最后查一次表**，确认开发已用时间和距收卷的剩余时间，再提交最终队伍。报告以裁判回执里的实际收件时间为准。

裁判用 10 个新种子对常规基准、高压基准各打 **20 局**，每个种子红蓝各打一局，分别报告红蓝成绩。开发试赛可以用小批量。正式交卷以收到并封存队伍为准，复验可以在收卷后结算。回放留作开发复盘。


# 工作台裁判接口

在本任务自己的工作目录写程序和试赛参数。公开材料包括 `赛题.md`、`完整规则.txt`、`平衡参数.md`、`API.txt`、`map.json`、`config.json`、`engine.cjs`。实际数值以公开配置和引擎为准，核心的提案顺序以赛题为准。公开观察和回放通过裁判接口提供。工具仅操作本队工作目录及本队的参赛资料。

- `node referee.cjs time_left` 查看当前阶段、开发剩余秒数和收卷截止。启动后先查表。如果接口仍在登记，等提示结束后重试。
- `node referee.cjs results @args.json` 可以读取黑盒批次，参数 `{"run":"baselines"}` 列出两个公开示例。用 `replay` 和参数 `{"run":"baselines","match":"baseline-practice-1","turn":20}` 查看附近回合。
- 在自己的队伍目录写六个角色模块和 `roster.json`。角色模块统一用 `require('./engine.cjs')`，裁判提供这个模块。需要本地运行时，可在队伍目录放一个名为 `engine.cjs` 的转接文件，内容为 `module.exports = require('../engine.cjs')`。执行 `node referee.cjs upload TEAM DIRECTORY` 上传本队程序和名单，工具会排除本地转接文件。
- `node referee.cjs run_trials @args.json`。参数 `{"candidate":"team","mode":"baselines","pairs":2}` 测两套基准，或 `{"candidate":"team","mode":"self","opponent":"another","pairs":2}` 让两套自选阵容换边互打。`replayPairs` 控制保存的回放数。每队可同时运行一批并保留一批排队请求。`queued: true` 表示裁判已接收排队，保存回执中的 `run`，用 `results` 查询即可。裁判记录因共享容量不足产生的等待，在批次开始后补时。
- 结束开发前保存最终代码，整理期可以检查已取得的比分和填写五个 ID。用 `set_roster` 更新名单。正式交卷前先单独运行 `node referee.cjs time_left`，紧接着运行 `node referee.cjs submit @args.json`，参数 `{"squad":"最终队伍名"}`。裁判以实际接受并封存的时刻为准。
- 用 `results` 确认出现 `formalReceivedAt`，最终回复提交名、五个 ID、核心和裁判回执上的交卷时间。正式复验是两套基准各 20 局，可以在截止后结算。

不要将任何参赛凭证、其他参赛者文件或裁判内部文件读入对话。正式练习、提交和成绩均以此处的裁判接口为准。
